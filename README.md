# ⚖️ Legal RAG Assistant — CFR Documents

> **A grounded AI assistant for searching, understanding, chatting about, and explaining U.S. Code of Federal Regulations (CFR) documents.**

Build a production-style **Retrieval-Augmented Generation (RAG)** system over legal PDF documents using **Qdrant**, **BGE embeddings**, **Groq LLMs**, and a **Self-RAG evaluation loop**.

The system can:

* 📄 Process large CFR PDF collections
* 🔎 Perform semantic document retrieval
* 🎯 Retrieve exact CFR sections
* 🧠 Use Self-RAG to judge retrieved context
* 💬 Answer legal questions using grounded sources
* 🗣️ Provide interactive CFR section chat
* 🎬 Generate grounded ~10-minute YouTube scripts
* 📚 Cite the source document and page
* 💾 Store vectors locally in Qdrant
* 🧩 Run each pipeline stage independently

# ✨ Features

## 📄 1. CFR PDF Processing

Place your CFR PDF documents inside:

```text
data/input_pdfs/
```

The system automatically:

* Finds PDF files
* Extracts text page-by-page
* Stores extracted text on disk
* Creates overlapping chunks
* Generates embeddings
* Indexes embeddings in Qdrant

---

## 🔎 2. Semantic Search

The system uses:

```text
BAAI/bge-base-en-v1.5
```

to convert text into vector embeddings.

User question:

```text
What authority does the Secretary have?
```

becomes a vector and is compared against the CFR vectors stored in Qdrant.

```text
Question
   │
   ▼
BGE Embedding
   │
   ▼
768-dimensional vector
   │
   ▼
Qdrant similarity search
   │
   ▼
Relevant CFR passages
```

---

# 🎯 3. Exact CFR Section Retrieval

If you provide a section such as:

```text
§386.48
```

the system attempts to identify and retrieve the **actual CFR section**, rather than relying only on semantic similarity.

Example:

```bash
python main.py ask "What does §386.48 require?"
```

This is especially useful for legal questions where exact section text matters.

---

# 🧠 4. Self-RAG

The project includes a Self-RAG-style judging step.

The system asks an LLM:

```text
Are the retrieved passages relevant?

Are they sufficient to answer the question?

Should the system answer or retrieve more information?
```

The judge returns structured information such as:

```json
{
  "relevant": true,
  "sufficient": true,
  "decision": "ANSWER",
  "reason": "The retrieved passages directly address the question."
}
```

Possible decisions include:

```text
ANSWER
RETRIEVE
NOT_RELEVANT
NOT_SUFFICIENT
```

# 🤖 Models Used

The project uses different models for different jobs.

| Component           | Model                   | Purpose                                 |
| ------------------- | ----------------------- | --------------------------------------- |
| 🧠 Embeddings       | `BAAI/bge-base-en-v1.5` | Convert CFR text/questions into vectors |
| ✍️ Text generation  | `openai/gpt-oss-120b`   | Generate answers and YouTube scripts    |
| ⚖️ Self-RAG Judge   | `openai/gpt-oss-20b`    | Evaluate relevance and sufficiency      |
| 🗄️ Vector database | Qdrant                  | Store and search embeddings             |
| ☁️ LLM provider     | Groq                    | Run the LLM models                      |

### Important

The embedding model **does not generate your YouTube script**.

The YouTube script is generated by:

```text
Groq
  ↓
openai/gpt-oss-120b
  ↓
YouTube Script
```

# 🔐 Grounding & Hallucination Control

The project is designed to minimize unsupported legal claims.

The answer generator is instructed to:

```text
Use supplied CFR material
        ↓
Do not invent legal requirements
        ↓
Do not invent section numbers
        ↓
Do not invent penalties
        ↓
Do not invent dates
        ↓
Do not invent procedures
        ↓
Cite source document/page
```

If the retrieved material is insufficient, the Self-RAG system can request additional retrieval rather than immediately generating an unsupported answer.

```text
legal-rag-assistant/
```

## `chunks.jsonl not found`

Run:

```bash
python main.py chunk
```

or rebuild everything:

```bash
python main.py pipeline
```

---

## `embeddings.npy not found`

Run:

```bash
python main.py embed
```

---

## Qdrant collection does not exist

Run:

```bash
python main.py index
```

---

## CUDA not available

The embedding system automatically selects:

```text
CUDA → if available
CPU  → otherwise
```

CPU works, but embedding a large PDF collection can take significantly longer.

---

## Qdrant locked

If you see a Qdrant lock error, close other processes using:

```text
data/book_assistant_data/qdrant_db/
```

Then run the command again.

# 📈 Performance Notes

Embedding is usually the most time-consuming stage when running on CPU.

Once the embeddings and Qdrant index are created, you **do not need to rerun the entire pipeline for every question**.

For normal usage:

```bash
python main.py ask "your question"
```

uses the existing Qdrant index.

Rebuild the pipeline only when your indexed data or embedding configuration changes.
